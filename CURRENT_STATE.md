## Реальная цепочка и точка продолжения

`Engine.create()` → `_initial()` / анализ Qwen → JSON/цитаты/FR → до трёх вопросов → `continue_run()` с ответами либо явным принятием допущений → `_design()` → `_finish()` → `render_documents()` / `write_files()` → `complete` для **документов**.

Цепочка заканчивается в `app/pipeline.py: Engine._finish()`, который совмещает валидацию, экспорт и завершение. Предполагаемое подключение генерации приложения - после проверенного v2-проекта в `_design()`, до финального `complete`; потребуется разделить промежуточное сохранение и финализацию. Это ещё не реализовано.

Работают конфигурация/диагностика Qwen, безопасные ошибки и метрики, анализ/вопросы/проектирование, один структурный repair на этап, экспорт/скачивание, валидация v1/v2 и OpenAPI, отчёт WKT, Markdown-адаптация. `specify_run.py --design` - инженерная ревизия без модели; обычный режим вызывает Qwen. `app/demo.py` - подготовленный пример, не анализ новых требований.

Не реализованы генерация приложения/миграций/тестовых данных, Angular/PWA, ASP.NET Core, БД/PostGIS, сборка, испытания приложения, CVE, целевой CI/CD/GitLab/deploy, мониторинг `/metrics`/`/health` и перезапуск. HTTP API `server.py` обслуживает пайплайн, а не парковочное приложение. Запуски хранятся в памяти, файлы - на диске; один активный запуск, автоматического восстановления нет.
