# Сетевой режим и выбор источника данных

Добавлен отдельный сетевой режим для уже проверенного парковочного API. Подключение устройства, токены только в памяти, правила повторов, сборка и фактические ограничения проверки описаны в [NETWORK.md](NETWORK.md).

При запуске пользователь явно выбирает «Подключить парковочный API» или «Автономное демо». Автоматического перехода к демо при сетевой ошибке нет. Следующее описание относится к сохранённому автономному прототипу; сетевой режим не вычисляет его события и не использует локальное демо-время.

# Парковка — нативный клиент водителя

Первоначальная ветка автономного прототипа — `phone`; текущая интеграция — `feature/backend`, файлы Android-проекта — `mobile/`. Ветка и папка решают разные задачи: ветка отделяет историю разработки, папка сохраняет отдельно уже существующий Angular-клиент `frontend/`.

Это первый **офлайн-прототип**, написанный на **Kotlin 2.2.21**, Jetpack Compose и Material 3 по кейсу Russtech. Не WebView, не PWA и не переписанная панель Python. Он демонстрирует поведение водителя, но пока не является готовым парковочным продуктом или универсальным генератором приложений.

## Что работает

- Экраны «Карта», «Сессия», «История», русские подписи, прокрутка и системные отступы.
- Явный демонстрационный маршрут: въезд, движение, переход к другому объекту, выезд, отсутствие координат, техническая ошибка, неоднозначное и устаревшее наблюдения, восстановление.
- Карта-схема с синтетическими объектами и пройденным маршрутом. Это **не географическая карта, не импорт `spb.json`, не тарифные зоны и не промышленный алгоритм определения зоны**. Координаты и результаты сопоставления заранее подготовлены только для демонстрации.
- Явный запуск сессии, подтверждение нового времени окончания, проверка длительности 1–1440 минут. Смена объекта и потеря координат не изменяют существующую сессию.
- Управляемые демо-часы, предупреждение при остатке не более 10 минут, однократное окончание сессии. Предупреждение не повторяется для одной ревизии; подтверждение нового срока создаёт новую ревизию.
- История сессий, событий и пройденных точек. Приватное локальное сохранение после каждого действия и восстановление после перезапуска. Ограничения: 100 сессий и 500 событий; явный сброс с подтверждением. Файлы приложения не включаются в Android backup.
- Платёжный адаптер явно возвращает `unavailable`, пока официальный URL не согласован. Действие показывает объяснение; оно не открывает произвольный сайт и никогда не устанавливает статус «оплачено».

В верхней части каждого экрана есть плашка демонстрационного режима; нижняя панель постоянно показывает «Демо · сервер не подключён», в том числе при прокрутке. В автономном режиме сетевые вызовы не выполняются. Геолокация не запрашивается. Основной manifest теперь содержит INTERNET для отдельно выбираемого сетевого режима. Реальный GPS, фоновые службы, системные push/уведомления и географическая подложка не подключены; HTTP и серверные сессии доступны только в новом режиме из NETWORK.md. Предупреждения показываются внутри приложения. Демо-время не идёт само и не совпадает с системным временем после перемотки.

## Инструменты

- Kotlin / Compose Compiler plugin: **2.2.21**.
- Android Gradle Plugin: **8.13.0**, Gradle Wrapper: **8.13**, JDK: **17** (в облаке Eclipse Temurin **17.0.21+9**).
- `compileSdk` / `targetSdk`: **36**, `minSdk`: **26** (Android 8+).
- Compose BOM **2025.10.01**, Activity Compose **1.11.0**, Lifecycle **2.9.4**.
- Для облака используются Command-line Tools **19.0**, SDK Platform 36, Build Tools **35.0.0**, platform-tools.

## Открыть в Android Studio

Откройте папку `mobile/` как проект, настройте Gradle JDK 17 и установите SDK 36 / Build Tools 35.0.0. Локальный `local.properties` с `sdk.dir` создаётся IDE, в Git не попадает.

```sh
cd mobile
./gradlew :app:assembleDebug :app:testDebugUnitTest
# Windows: gradlew.bat :app:assembleDebug :app:testDebugUnitTest
```

APK: `app/build/outputs/apk/debug/app-debug.apk`. Это отладочная подпись для демонстрации, не release-пакет для магазина. В облаке локальный ключ создаётся в игнорируемой `.tooling/android-home/`, в обычной среде — в стандартном каталоге Android пользователя. Ключ нельзя коммитить.

Установка на Android через USB:

```sh
adb install -r app/build/outputs/apk/debug/app-debug.apk
adb shell am start -n ru.russtech.parking.demo/ru.russtech.parking.MainActivity
```

APK не устанавливается на iPhone. Для iPhone понадобится отдельное решение; данный этап — нативный Android согласно PDF.

## Сборка в Linux-облаке без Android Studio

Из `mobile/`:

```sh
./scripts/bootstrap-linux.sh
./scripts/gradle-cloud.sh :app:assembleDebug :app:testDebugUnitTest
```

Bootstrap скачивает инструменты только с официальных серверов Google, Gradle и Eclipse Adoptium/GitHub. До распаковки проверяет опубликованные контрольные суммы: Gradle/JDK — SHA-256, Command-line Tools — checksum официального Android repository manifest. TLS-проверка не отключается. Android SDK Manager проверяет свои пакеты и запрашивает лицензии; bootstrap принимает лицензии для этой dev-среды.

SDK/JDK, кэши Gradle и локальные данные хранятся в игнорируемой `.tooling/`. Скрипт сборки учитывает существующий `HTTPS_PROXY`; при наличии предоставленного средой CA добавляет его к копии стандартного truststore. Значения паролей, ключей и прокси-учётных данных в проект не записываются. Произвольная замена сертификатов и отключение проверки не используются. На обычной машине можно использовать Gradle Wrapper напрямую.

## Сценарий демонстрации

1. Откройте приложение. Убедитесь, что показана плашка тестового режима.
2. На «Карте» нажмите «Следующая точка маршрута»: определится демо-объект А.
3. Нажмите «Запустить сессию», оставьте 30 минут, подтвердите. Это не подтверждение оплаты.
4. Перейдите на «Сессию», дважды нажмите `+10 мин`: останется 10 минут и появится предупреждение.
5. На «Карте» перейдите через следующую точку к объекту Б: сессия А сохранится, будет предложение проверить оплату.
6. Продолжите маршрут: выезд, отсутствие координат, ошибка и неопределённые наблюдения. Они не объявляют парковку бесплатной и не создают новую оплату.
7. Ещё `+10 мин`: сессия истечёт. Просмотрите историю и события.
8. Закройте и снова откройте приложение: локальное состояние должно сохраниться. Для повторения начального сценария используйте «Сбросить» и подтвердите удаление демо-данных.

## Источники и серверная интеграция

Исходный кейс требует **нативное Android-приложение Kotlin 2.2.21** и отдельный административный Angular-интерфейс. Сохранённая инженерная спецификация [`../examples/parking-contracts-reviewed.json`](../examples/parking-contracts-reviewed.json) пока называет клиент PWA. Оригинал не исправлялся: точная копия и SHA-256 находятся в `contracts/`; расхождение явно отмечено в `contracts/source.json`.

В интерфейсе `ParkingRepository` отделены операции получения состояния, позиций, сессии, времени и платёжного адаптера. Этот интерфейс используется автономным `DemoRepository`. Новый отдельный `ParkingApi`/`ParkingHttpApi` реализует сетевой профиль сессий (см. NETWORK.md), но его сборка и настоящий Android-сценарий в текущем окружении не проверены.

За пределами текущих пяти операций сетевого профиля для дальнейшего развития предусмотрены операции из сохранённого контракта: `/api/vehicles`, позиции и match автомобиля, `/api/parking-objects/{objectId}`, сессии и confirm, payment-link, маршруты, позиции и уведомления. **`/api/notes` — другой проверочный API, он не обслуживает парковочный клиент.** Смена положения не должна означать автоматическую смену оплаченной сессии, а отсутствие совпадения — бесплатность.

Для пяти текущих операций адрес, OpenAPI, демонстрационные водители и данные предоставлены и описаны в NETWORK.md. Для дальнейших функций нужны оставшиеся серверные операции и официальный разрешённый URL оплаты. Автоматической подмены настоящего сервера нет. Доступы к ВМ и Qwen приложению не нужны.

Для внешнего доступа планируется HTTPS API через **443**. Порт 80 может перенаправлять на HTTPS; 8080 не является обязательным и остаётся на усмотрение владельца сервера. В текущей офлайн-версии ни один из этих портов не используется. Открытие порта не заменяет настройку сервера и сертификата.

## Проверки и ограничения

Исторические результаты автономного прототипа до добавления сетевого режима (это не повторная проверка текущих исходников; текущий блокер JDK/SDK описан в NETWORK.md):

- `:app:assembleDebug` — успешно; универсальный debug APK около 11 МБ. `apksigner verify` подтверждает подпись APK v2, manifest указывает minSdk 26 / targetSdk 36.
- `:app:testDebugUnitTest` — **29 тестов прошли**, пропусков и ошибок нет: 16 тестов предметной логики, 5 — репозитория, 6 — JSON-снимков, 2 — Compose-интерфейса.
- UI-проверки выполнены через **Robolectric 4.16.1 с Android API 35 и native graphics**, а не на физическом устройстве. Проверены запуск сессии, предупреждение за 10 минут, неоплаченный статус, валидация длительности и подтверждённый/отменённый сброс. Ввод времени вынесен в основной экран приложения. Смена вкладки возвращает прокрутку к началу.
- Скриншоты карты и сессии получены нативным Canvas-рендерером Robolectric и просмотрены; файлы — `app/build/reports/screenshots/` (игнорируются Git). PixelCopy-снятие окна не используется: его redraw callback не поддерживается этой тестовой средой.
- `:app:lintDebug` — **0 ошибок, 3 предупреждения**: доступны более новые версии двух тестовых библиотек; предложена KTX-обёртка для SharedPreferences. Прямой `commit()` сохранён намеренно, чтобы проверять результат записи и не публиковать состояние при ошибке хранения. Проверки Lint не отключались.
- Исходный парковочный контракт и его SHA-256 сохранены. Изменений в сервере, исторических результатах, схемах и `frontend/` нет.

Для полного повторения в облаке:

```sh
./scripts/gradle-cloud.sh :app:assembleDebug :app:testDebugUnitTest :app:lintDebug
```

**Установка и работа на физическом Android-устройстве ещё не проверены. Настоящая серверная интеграция не выполнена.** Успешная JVM-проверка интерфейса не равнозначна испытанию GPS, фона, реального времени и доступа к серверу.

Android-приложение написано вручную, Qwen не вызывался. Сервер, БД, инфраструктура, исторические контракты и Angular-клиент не меняются. Наличие этого прототипа не подтверждает выполнение полного кейса, серверной синхронизации, административного интерфейса или генерации приложений для скрытого задания.
