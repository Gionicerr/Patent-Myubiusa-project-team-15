# Сетевой режим парковки

В главном меню явно выбирается **«Подключить парковочный API»** или **«Автономное демо»**. Автоматического перехода к демо при ошибке нет. Сетевой режим не использует DemoParkingEngine, DemoRepository и сохранённый локальный снимок. Текущие сессии и ревизии читаются с сервера.

## Доступ телефона к API

API на vm15 — `127.0.0.1:43221`. На компьютере должен работать ранее настроенный туннель:

```sh
ssh -N -o ExitOnForwardFailure=yes -p 10015 -L 18881:127.0.0.1:43221 team15@85.143.113.230
```

Переиспользуйте уже работающий туннель. Не открывайте порт ВМ публично.

Для USB-устройства разрешите USB debugging, подтвердите доверие компьютеру и выполните (заменив SERIAL):

```sh
adb devices -l
adb -s SERIAL reverse tcp:18881 tcp:18881
adb -s SERIAL reverse --list
```

После этого вводимый в приложении адрес — **`http://127.0.0.1:18881`**. Без reverse это localhost самого телефона, а не компьютера. Для стандартного Android Emulator альтернативный маршрут — **`http://10.0.2.2:18881`**, специальный адрес хоста. [Документация Android: доступ к локальному серверу](https://developer.android.com/develop/ui/views/layout/webapps/access-local-server).

INTERNET добавлен в основной manifest. Локальный HTTP разрешён только debug-конфигурацией и только для 127.0.0.1/10.0.2.2; основная/release-конфигурация сохраняет usesCleartextTraffic=false. Дополнительно адаптер запрещает HTTP вне debug и запрещает URL с учётными данными, путём, query или fragment. Перенаправления HTTP не выполняются, проверка TLS не отключается. [Network Security Configuration](https://developer.android.com/privacy-and-security/security-config).

Водительские токены — DEMO_TOKEN_A и DEMO_TOKEN_B в защищённом файле на ВМ:
`/home/team15/rwb-parking-api-20261031/runs/parking-sessions/runtime.env`.

Пользователь получает необходимый токен через приватный SSH-доступ и вводит в парольное поле. Не сохраняйте его в исходниках, параметрах сборки, URL, отчётах, скриншотах или снимках приложения. Поле очищается при подключении, токен остаётся только в памяти сетевой ViewModel и запроса. При отключении, выходе из сетевого режима и завершении ViewModel сеанс очищается. При пересоздании Activity снова требуется явный выбор режима и подключение. Сетевая информация не записывается в SharedPreferences/LocalStateStore.

## Сценарий

1. Выберите сетевой режим, проверьте адрес и подключитесь водительским токеном.
2. Списки автомобилей и объектов загружаются асинхронно с пагинацией items/page/pageSize/total. Выберите автомобиль и объект явно. Для первой демонстрации предусмотрены **DEMO-CLIENT-A** у driver-a и **DEMO-CLIENT-B** у driver-b; UUID берутся из API, не из локальных demo-a/demo-b.
3. После выбора автомобиля обязательно читаются его сессии. Укажите будущее endAt в ISO 8601 с часовым поясом, например дату/время в UTC с суффиксом Z. Поле по умолчанию содержит реальное текущее время устройства плюс час; окончательное решение о допустимости принимает сервер. Локальное демо-время и миллисекунды не отправляются.
4. Нажмите «Создать сессию на сервере». Отправляются только objectId, endAt и idempotencyKey. После ответа перечитывается серверный список; оплата остаётся неподтверждённой.
5. Выберите серверную сессию, измените endAt и подтвердите новое время. Отправляются только endAt, expectedRevision из загруженной сессии и новый idempotencyKey. Объект сессии при подтверждении не меняется.
6. В интерфейсе показаны точные серверные id, revision, startedAt и endAt. После изменения откройте административную страницу `http://127.0.0.1:4200/admin/parking`, обновите сессии и сравните id/revision/endAt (один и тот же момент времени, учитывая формат UTC/offset).

Список active/expired приходит с сервера. Приложение не вычисляет переходы, не запускает сопоставление координат, уведомления, оплату или демо-перемотку. Эти возможности явно обозначены как недоступные.

## Повторы и ошибки

- Один явный create/confirm создаёт один неизменяемый SessionAction с UUID-ключом и готовой строкой JSON. Новый пользовательский запрос получает новый ключ.
- При тайм-ауте, сети, 5xx или некорректном успешном ответе результат может быть неизвестен. Поля/выбор блокируются, доступна кнопка «Повторить тот же запрос». Повтор использует исходные path, тело, endAt, expectedRevision и ключ — без автоматического пересчёта времени или ревизии. Автоматических POST-повторов нет.
- 409 не маскируется: сессии перечитываются перед новым действием. Если повторное чтение не удалось, создание/подтверждение заблокировано до успешного чтения. Новое подтверждение берёт актуальную ревизию из перечитанной сессии.
- При активной сессии предлагается выбрать её и подтвердить время вместо второй активной сессии. Клиент ничего не удаляет из БД.
- 401/403, 400/422, 404 и сеть имеют фиксированные безопасные сообщения; необработанные серверные ошибки не отображаются и не журналируются.
- Pending-запрос хранится только в памяти. Если процесс потерян или пользователь явно отключился в момент неопределённого результата, старый ключ больше недоступен: после подключения сначала прочитайте серверные сессии и не создавайте/не подтверждайте действие вслепую.

Используются только listVehicles, listObjects, createSession, listVehicleSessions, confirmSession из `contracts/parking-contracts-reviewed.json`. IdempotencyKey находится в JSON, не в заголовке. Никаких административных операций Android не вызывает.

## Сборка и проверка

С JDK17 и Android SDK36 в `mobile/`:

```powershell
.\gradlew.bat assembleDebug testDebugUnitTest
adb -s SERIAL install -r app/build/outputs/apk/debug/app-debug.apk
```

Профильные тесты адаптера и ViewModel:

```powershell
.\gradlew.bat testDebugUnitTest --tests 'ru.russtech.parking.network.*' --tests 'ru.russtech.parking.ui.NetworkParkingViewModelTest'
```

`ParkingHttpApiTest` использует подменённый HttpTransport, `NetworkParkingViewModelTest` — подменённый ParkingApi и Robolectric. Они проверяют DTO/страницы, асинхронность, ключи и тела повторов, ошибки и обязательное перечитывание после 409. Это не доказательство настоящего Android/API/БД-сценария. Существующие UI-тесты автономного режима теперь явно выбирают его в меню.
