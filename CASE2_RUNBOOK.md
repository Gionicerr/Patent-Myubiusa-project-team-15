## Уточнения и проектирование

Ответьте на фактические вопросы в той же панели. API-механизм: POST `/api/runs/RUN_ID/continue` с `answers`, где ключи — ID вопросов; требуется CSRF-сеанс панели. Допущения принимаются только явно. Пауза сохраняет analysis.json/pending-report.json, но сама очередь вопросов после перезапуска процесса автоматически не восстанавливается. Сохраняйте исходный текст и ответы отдельно до перезапуска.

После ответов Engine вызывает Designer (`design-parts-2`) и затем `_finish()`: анализ, design v2, OpenAPI, документы и метрики. Веб-режим не начинает генерацию приложения автоматически. При неудаче проектирования контрольная точка и принятые части сохраняются; в панели предусмотрено продолжение проектирования (POST `/api/runs/RUN_ID/resume-design`).

Отдельный CLI по **анализу нового кейса**, если нужно проектировать/продолжить вне панели:

```sh
python specify_run.py --requirements /home/team15/case2-results/input/requirements.md --analysis /home/team15/case2-results/analysis/RUN_ID/analysis.json --answers /home/team15/case2-results/input/answers.json --output /home/team15/case2-results/specification
# Только для контрольной точки этого же CLI-каталога и тех же входов:
python specify_run.py --requirements /home/team15/case2-results/input/requirements.md --analysis /home/team15/case2-results/analysis/RUN_ID/analysis.json --answers /home/team15/case2-results/input/answers.json --output /home/team15/case2-results/specification --resume
```

answers.json — объект ID вопроса → текст ответа; при отсутствии вопросов опцию можно убрать. Не запускайте параллельно проектирование одного результата через CLI и панель. Не создавайте новый запуск для обхода 429. `--context` принимает компактную сводку источников; `--max-tokens`/`--timeout` — явные настройки, не автоматическое повышение. Несовместимую контрольную точку нельзя продолжить: остановиться и сохранить причину. Совместимость включает входы, версию планировщика и размеры пакетов. Старые метрики не стираются.

**Общего автоматического прохода до любого приложения нет.** Отдельный малый серверный генератор:

```sh
python generate_server.py --analysis /home/team15/case2-results/analysis/RUN_ID/analysis.json --design /home/team15/case2-results/specification/design.json --output /home/team15/case2-results/server --verify --sudo-docker
```

Его запуск допустим только после проверки соответствия профилю: одна сущность, ровно POST-create и GET-list, поддержанные примитивные ненулевые поля/ограничения, без связей и составных ограничений. Полный перечень ограничений проверяет `app/server_generation.py`; произвольный кейс может быть отклонён. Существуют `--resume` для split-file режима и `--accepted-run` с точным `--accepted-sql-sha256` для принятого SQL **того же контракта**; не переносите SQL заметок в другой кейс. Текущий split-file ответ может упереться в лимит. Генератор парковки — отдельный профиль шести фиксированных операций, не универсальная альтернатива для кейса 2.

Angular/Android по произвольному новому v2 автоматически не генерируются. Новую бизнес-логику вручную в исходники пайплайна после стоп-кодинга не дописывать. При неподдержанном профиле показать честный результат анализа/проектирования и конкретный разрыв, а не подставлять старый контракт. Сборка требует существующих SDK/Docker; статус успешности берётся только из фактических журналов. HTTP 429, недоступность и finish_reason=length сохраняются как блокеры.

Точки входа и аргументы проверены через `--help` без обращений модели. Текущий фиксированный технологический профиль передаётся анализу, PWA выбирается по мобильным требованиям.
