# Регламенты документации Russtech

Это адаптация пяти документов организаторов для Markdown в репозитории. Документы задают требования к описанию и будущим этапам, а не поручение реализовать все упомянутые возможности сейчас.

## Состав

- [Реестр исходников, страниц и SHA-256](sources.json); неизменённые PDF находятся в `originals/`.
- [Компактные правила](rules.md), [соответствие форматам проекта](mapping.md), [пробелы и будущие задачи](backlog.md).
- [Протокол проверки извлечения](extraction-review.md); `extracted/` содержит текст с номерами страниц и таблицы, `extraction-audit.json` - техническую статистику.
- Шаблоны: [системный анализ](templates/system-analysis.md), [метод API](templates/api-method.md), [сервис](templates/service.md), [ADR](templates/adr.md), [исходник диаграммы PlantUML](templates/sequence.puml).
- [Адаптированная документация stage2](../../../docs/stage2/README.md). Примеры и неполные разделы явно обозначены; согласования не заявляются.

Классы положений: **M** - явно требуемое описание; **R** - рекомендация; **E** - пример/справочник; **U** - применимость или трактовка требуют уточнения. Класс не означает, что раздел заполнен или механизм реализован. Статус выполнения указан отдельно в таблице соответствия.

При расхождении источников сохраняются оба указания и открытый вопрос. Устранение расхождений не переименовывает FR и API текущего контракта. Числовые значения и технологии внутри примеров не становятся требованиями проекта.
