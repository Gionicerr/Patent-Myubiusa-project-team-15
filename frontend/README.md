# Клиент заметок

Angular-клиент целевого приложения: создание и просмотр собственных заметок. Это отдельный интерфейс от Python-панели пайплайна в `static/`. Изменения этого этапа находятся только в `frontend/`.

## Версии и установка

Фактически использованы Node.js **24.19.0**, npm **11.9.0**, Angular / CLI / Material / CDK **20.1.6**, TypeScript **5.8.3**. Прямые зависимости закреплены точными версиями, транзитивные — в `package-lock.json`.

[Официальная таблица Angular](https://angular.dev/reference/versions): для Angular 20.0/20.1 совместимы Node `^20.19.0 || ^22.12.0 || ^24.0.0`, TypeScript `>=5.8.0 <5.9.0`. В `.nvmrc` записана использованная версия Node. Все команды ниже выполняются из `frontend/`:

```sh
npm ci
```

npm использует локальный игнорируемый кэш `.npm-cache/`. Не требуется устанавливать Python-пакеты, запускать Qwen, Docker или серверную генерацию.

## Режим тестовых данных

```sh
npm run start:mock
```

Dev-сервер использует порт 4200. `/` перенаправляет на `/notes`. Нажмите **«Начать тестовый сеанс»** — будет использован явно фиктивный токен. Список первоначально пуст; добавленные заметки хранятся в памяти вкладки. Перезагрузка страницы удаляет тестовые данные. Можно задать другой фиктивный токен, чтобы проверить смену сеанса и независимые списки.

Постоянная плашка **«Тестовые данные. Сервер не подключён»** обозначает подмену. Этот режим не обращается к настоящему API. Он включается отдельной сборочной конфигурацией `mock`, а не URL-параметром или реакцией на ошибку сети.

Для воспроизведения ошибок тестовый транспорт предоставляет `MockNotesGateway.failNext('list' | 'create', status)`. Его проверки используют 400, 401, 403, 500 и 0 (сетевая ошибка). Большая панель отладки в продукт не добавлена.

## Режим настоящего API

В POSIX-терминале:

```sh
NOTES_API_URL=http://127.0.0.1:18880 npm start
```

В PowerShell:

```powershell
$env:NOTES_API_URL = 'http://127.0.0.1:18880'
npm start
```

**18880 — только пример.** Подставьте фактический origin готового ASP.NET API из `generation-report.json` / от владельца сервера. Это не адрес Python-панели на 8765/18765. Адрес не должен содержать путь, параметры или учётные данные. При отсутствующем `NOTES_API_URL` команда явно завершается с подсказкой, не направляя запросы на произвольный сервер.

`proxy.conf.cjs` направляет `/api/notes` на указанный origin с сохранением пути. Проверка TLS включена. При изменении origin перезапустите только собственный Angular dev-сервер. CORS сервера менять не нужно. Для API на ВМ владелец серверной части готовит туннель; в переменную записывается адрес его локального конца.

В интерфейсе введите **демонстрационный токен приложения** в маскированное поле и нажмите «Подключиться». Это не API-ключ Qwen и не корпоративная регистрация. Токен хранится только в памяти текущей вкладки, поле очищается после подключения. Он не записывается в browser storage, URL, исходники или журналы; приложение добавляет Bearer только к двум операциям заметок. Не передавайте токен в командной строке, `.env` клиента или конфигурации сборки.

При смене / завершении сеанса данные, черновик и состояния предыдущего сеанса очищаются, запросы отменяются, запоздалые результаты не применяются. В настоящем режиме ошибка остаётся ошибкой: автоматической подмены данными нет. Изоляцию владельцев и права проверяет сервер.

## Контракт

Источник: [`../examples/notes-server-design-v2.json`](../examples/notes-server-design-v2.json), требования — [`../examples/notes-server-analysis.json`](../examples/notes-server-analysis.json), происхождение — [`../examples/notes-server-provenance.json`](../examples/notes-server-provenance.json).

Точная копия исходного design сохранена в [`contracts/notes-server-design-v2.json`](contracts/notes-server-design-v2.json); путь и SHA-256 исходных байтов — в [`contracts/source.json`](contracts/source.json). Этот контракт подготовлен инженерно, не объявляется результатом Qwen. Указанный в передаче сохранённый OpenAPI отсутствует в текущем клоне; использован design v2. Схемы полей и операций в нём соответствуют переданным договорённостям. Ограничение заголовка из пробелов дополнительно задано в клиентском задании.

| Операция | Запрос | Успешный ответ |
| --- | --- | --- |
| `listNotes` | `GET /api/notes`, без параметров и тела | `200`, непосредственно `Note[]` |
| `createNote` | `POST /api/notes`, `{title, text?}` | `201`, `Note` |

`Note` содержит `id`, `ownerId`, `title`, `text`, `createdAt` (все строки; время ISO 8601). POST отправляет только `title` и необязательное `text`; серверные поля не передаются. Заголовок обязателен, не может состоять только из пробелов, максимум 100 символов; текст необязателен, максимум 2000. Клиент не обрезает и не нормализует ввод молча. Дата показана в местном времени браузера; порядок элементов не навязывается контракту.

Ошибки `{code, message}` обрабатываются по HTTP-статусу с русскими сообщениями для 400, 401, 403, 500 и сети. Сырые HTML/тела ошибок не показываются и не журналируются. Ответы успешных операций проверяются на ожидаемую форму. Повторов запросов нет. При неопределённом результате POST (сеть, серверная ошибка, некорректный ответ) черновик остаётся; повторная отправка блокируется до успешной явной проверки списка. Если POST подтверждён, но последующий GET не удался, интерфейс отдельно сообщает, что заметка создана, а список не обновлён.

## Сборка и проверки

```sh
npm run build
# результат: dist/notes/browser/
```

Production-сборка использует настоящий HTTP-транспорт. Размещение статики и проксирование `/api` в production согласуются отдельно: нужен same-origin API и fallback `/notes` на `index.html`. Dev-прокси не входит в production-артефакт. Для тестовой сборки при необходимости: `npx ng build --configuration mock` — это подмена, не настоящая интеграция.

Для тестов нужен Chromium/Chrome. В этой среде проверено с `/usr/bin/chromium`:

```sh
CHROME_BIN=/usr/bin/chromium npm test
CHROME_BIN=/usr/bin/chromium npm run test:e2e
```

В PowerShell задайте `$env:CHROME_BIN` как путь к Chrome перед запуском. Для Jasmine/Karma можно не задавать путь, если Chrome обнаруживается автоматически. Для Playwright без системного браузера сначала `npx playwright install chromium`, затем `npm run test:e2e`. Флаги `--no-sandbox` в тестовых launchers предназначены для Chromium в контейнере, не меняют проверку TLS/API.

- **39 Jasmine/Karma-проверок прошли**: HTTP-контракт и Bearer, границы полей, реальные события формы, загрузка / пустой список, создание, блокировка повторов, сохранение черновика, ошибки 400/401/403/500/сети/неожиданного ответа, смена токена и отмена старых запросов, безопасный вывод текста, изоляция тестовых сеансов.
- **5 Playwright-проверок прошли в настоящем Chromium**: полный сценарий подмены на 1440×1050 и 390×844 без горизонтального переполнения; HTTP GET → POST → GET с перехватом и проверкой тела / заголовков; отказ реального HTTP-пути при недоступном API без перехода к подмене; 401 и сохранение черновика.
- Скриншоты широкого и узкого экранов создаются внутри игнорируемой `test-results/`. Консольные ошибки страницы в двух сценариях подмены проверяются тестами. Скриншоты просмотрены.
- `npm ci` по lock-файлу и production-сборка проверены. Общий серверный набор тестов не запускался: серверные файлы не менялись.

Playwright сам поднимает **свои** два Angular dev-сервера на 4200/4201 и останавливает их; занятые порты не переиспользует. Для ошибки подключения используется намеренно недоступный локальный порт 9. HTTP-перехват в браузерных тестах — это проверка клиента, не настоящая интеграция ASP.NET/PostgreSQL.

**Интеграция с настоящим API не выполнена.** Готовый адрес и демонстрационные токены владельцем сервера не предоставлены. Для неё нужны фактический API origin (или локальный адрес туннеля), подтверждение готовности GET/POST и действующие токены двух тестовых владельцев, переданные безопасно. После получения — проверить GET → POST → GET и отдельно изоляцию владельцев. Значения секретов в отчёты не включать.

## Границы этапа

Реализованы только список и создание заметок. Парковочный интерфейс, карта, PWA, редактирование / удаление / поиск, регистрация, универсальный генератор клиента, общая упаковка, развёртывание и серверные изменения не входят в этот этап. Этот клиент написан вручную; происхождение от модели не заявляется. `main` не объединяется, Git-коммиты и отправка изменений остаются пользователю.
# Административная парковочная страница

Адрес: **http://127.0.0.1:4200/admin/parking**. Маршрут `/notes` и его транспорт сохранены. Парковочная страница всегда использует настоящий HTTP; mock-провайдер заметок на неё не влияет. Используются только GET `/api/vehicles`, GET `/api/parking-objects?city=spb`, GET `/api/admin/sessions` с необязательным vehicleId.

Каждый список имеет независимую пагинацию items/page/pageSize/total и обновление. Фильтр сессий принимает UUID автомобиля; пустое поле снимает фильтр. Показаны автомобиль, объект, startedAt, endAt, status, revision, paymentConfirmed. До загрузки справочных имён показываются UUID. Время отображается в часовом поясе браузера; price — без пересчёта единиц. Редактирования сессий нет.

## Подключение парковки

API на vm15: `http://127.0.0.1:43221`. На компьютере разработчика нужен туннель. Переиспользуйте действующий туннель на 18881, если он уже запущен:

```sh
ssh -N -o ExitOnForwardFailure=yes -p 10015 -L 18881:127.0.0.1:43221 team15@85.143.113.230
```

Dev-proxy сохраняет пути и направляет только `/api/vehicles`, `/api/parking-objects`, `/api/admin/sessions` в PARKING_API_URL (по умолчанию http://127.0.0.1:18881). `/api/notes` остаётся на отдельном NOTES_API_URL. Общего перенаправления `/api` нет; прокси не добавляет токены.

Из `frontend/`, после `npm ci`, в PowerShell:

```powershell
$env:NOTES_API_URL = 'http://127.0.0.1:18880'
$env:PARKING_API_URL = 'http://127.0.0.1:18881'
npm start -- --host 127.0.0.1 --port 4200
```

NOTES_API_URL должен соответствовать существующему отдельному адресу заметок. Для ранее проверенного сервера заметок туннель при необходимости: `ssh -N -p 10015 -L 18880:127.0.0.1:36309 team15@85.143.113.230`. Этот этап его не запускает и не проверяет заметочный API.

Если npm отсутствует в PATH, но зависимости установлены, эквивалентный запуск: `node node_modules/@angular/cli/bin/ng.js serve --configuration development --proxy-config proxy.conf.cjs --host 127.0.0.1 --port 4200`.

Защищённый файл на ВМ: `/home/team15/rwb-parking-api-20261031/runs/parking-sessions/runtime.env`. Для административного списка нужен **DEMO_TOKEN_ADMIN**. DEMO_TOKEN_A/B — водительские токены: для административного списка они получают 403. Получайте нужное значение через приватный SSH-доступ; не помещайте файл/токен в переписку, Git, URL, конфигурацию frontend или журналы. Вставьте токен в поле страницы. Поле очищается при подключении. Токен хранится только в памяти: отключение, уход со страницы и перезагрузка удаляют сеанс. localStorage/sessionStorage/cookies для токена не используются.

Предусмотрены загрузка, пустой результат, 401, 403, сетевая ошибка и неожиданный формат. Сырые тела ошибок не отображаются и не журналируются. Права проверяет сервер; сам факт подключения токена не подтверждает роль администратора.

## Контракт и проверки парковочной страницы

Копия исходной спецификации: `contracts/parking-contracts-reviewed.json`; источник и SHA-256 нормализованного UTF-8/LF текста — `contracts/parking-source.json`. Типы спроецированы в `src/app/admin/parking-models.ts`. Полный контракт описывает будущие операции; текущая страница использует только три GET выше.

```sh
npm run build -- --configuration production
npm test -- --progress=false
npm run test:parking-proxy
```

`scripts/test-parking-live.mjs` проверяет настоящий API в Playwright. PARKING_UI_URL задаёт адрес страницы (по умолчанию http://127.0.0.1:4200), CHROME_BIN — путь к установленному Chrome/Edge. Приватный JSON с полями admin/driver передаётся **только через stdin**, не сохраняется в файл. Не записывайте его в Git или журналы. Пример для приватной SSH-сессии: stdout SSH передаётся прямо в stdin Node; значения не выводятся в общий журнал:

```powershell
@'
import json
from pathlib import Path
values=dict(line.split('=',1) for line in Path('/home/team15/rwb-parking-api-20261031/runs/parking-sessions/runtime.env').read_text().splitlines() if '=' in line)
print(json.dumps({'admin':values['DEMO_TOKEN_ADMIN'],'driver':values['DEMO_TOKEN_A']}))
'@ | ssh -o StrictHostKeyChecking=yes -p 10015 team15@85.143.113.230 python3 - | node scripts/test-parking-live.mjs
```

Результаты этапа (31.10.2026, Москва): production-сборка успешна, **58/58 клиентских тестов** и проверки прокси прошли. В Edge headless через настоящий API проверены административный список 200, пустой результат для свободного автомобиля, водительский 403, отсутствие токена после перезагрузки и доступность маршрута заметок. Парковочные запросы были только GET; сессии не создавались, серверы и БД на ВМ не изменялись. Полный прежний e2e-набор заметок не выполнялся.

Есть предупреждение размера initial bundle: 524.35 kB при warning-бюджете 500 kB; error-бюджет 1 MB не превышен, лимиты не менялись. В демонстрационной БД две активные сессии и свободные DEMO-CLIENT-A/B. Объекты — выборка spb, не полный импорт. Подключение mobile, публичный доступ, TLS и отсутствующие операции не входят в этот этап.
